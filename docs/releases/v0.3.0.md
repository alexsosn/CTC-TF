# Ugarit Context Parsing v0.3.0

This is the first stable GitHub release of the Burns Workbooks materializer.

## What users get

- **Feature-only CUC module as the primary product.** `ugarit-context-parsing module`
  verifies the exact reviewed Copenhagen Ugaritic Corpus (CUC) base and writes
  ordinary Burns node/edge features over **existing CUC nodes only**. The module
  owns no nodes and writes no `otype.tf`, `oslots.tf`, or replacement
  `otext.tf`.
- **Queryable exact Burns occurrences without JSON blobs.** Exact lexical
  occurrences are carried by the first CUC word of their span in deterministic
  lane-numbered scalar features such as `burns_headword_N`,
  `burns_match_rule_N`, `burns_category_N`, `burns_semantic_status_N`, and
  `burns_span_length_N`. A `burns_span_N` edge points from the carrier to
  subsequent CUC words of a multiword occurrence. `burns_match_rule_N` preserves
  whether the span came from literal matching, the evidenced parenthesis-core
  rule (including the opaque-inner-group variant), or one side of an evidenced
  slash alternative.
- **Lossless overlap/multiplicity.** Multiple independent annotations sharing the
  same start word receive separate deterministic lanes. The current real source
  reaches lane depth 6 after headword-expression recovery; lane count is derived
  dynamically rather than frozen to a corpus snapshot.
- **No coarse lexical fallbacks in public TF features.** `HEADWORD_NOT_FOUND`,
  ambiguous lexical/structural cases, out-of-CUC references, and non-textual
  entries remain in the local audit report rather than being attached to CUC
  line/tablet nodes as lexical claims.
- **Tablet-scoped excavation observations.** `burns_locus`, `burns_room`,
  `burns_point`, `burns_depth`, and `burns_disputed` are published only on
  an existing CUC tablet when all mapped Workbook observations agree.
- **CSV and PDF inputs.** Generated Workbook CSV directories and the original
  Workbook PDFs use the same normalization, alignment, audit, and publication
  model.
- **Exact CUC compatibility contract.** Materialization is bound to
  `DT-UCPH/cuc@ad69400f5446e1c8217af01659c7c10ab00c015b`,
  `tf/0.2.8`, with reviewed file fingerprints before publication.
- **Context-Fabric/cfabric-mcp composition.** Load CUC first and the Burns module
  second. CI verifies native lane queries, multiword span edges, tablet findspots,
  and an unchanged CUC warp through the pinned consumer.
- **One-shot publication.** The corrected module requires an absent output
  directory, stages a complete artifact, and publishes it with an exclusive
  no-replace operation.
- **Explicit compatibility paths.** `ugarit-context-parsing module-v1` retains
  the previous six JSON-valued CUC feature-module format for rollback. The older
  standalone `convert` command is retained but deprecated.

The experimental extended-warp `entities` CLI and Burns-created annotation nodes from the pre-release #68/#69 design are not part of this release.

## Real-source acceptance and known boundaries

The release gates parse the pinned Burns Workbooks runner-locally:

- 45 worksheets;
- 13,857 source rows;
- 10,419 normalized annotations;
- 7,402 exact lexical occurrences;
- 5,909 distinct CUC start words carrying those occurrences;
- lane-depth distribution: 4,837 starts at depth 1; 724 at depth 2; 303 at
  depth 3; 30 at depth 4; 2 at depth 5; 13 at depth 6;
- current maximum real-source lane depth: 6.

The matcher now has source-grounded bounded handling for two authored headword
expression classes. For one balanced non-nested parenthesized group, the lexical
candidate is the core with the parenthesized group omitted: real cited-line
research found 2,873 unique core matches and **zero** occurrences that required
the expanded parenthesized expression. For one token-internal slash, left and
right branches are exact alternatives; both sides are independently attested in
the cited lines. Multiple exact candidate spans remain explicit ambiguity. A third narrow rule
allows bracket/slash markup to remain opaque when it is wholly inside the same
parenthesized group already omitted from the lexical core. Real-source research
found 149 unique exact cores and one repeated/ambiguous core in this class; no
surviving bracketed lexical characters produced a supported exact case requiring
CUC restoration evidence.

Another 1,841 occurrences resolve structurally to a CUC line but do not establish
an exact lexical span under the current matcher, and 276 resolved-line
occurrences have ambiguous exact spans. Square brackets that survive into the
lexical core and other complex/mixed headword expressions remain fail-closed
research boundaries.

A candidate-aware ±1/±2 line-address audit on the residual 1,841 misses finds
209 unique neighbor rescues, 36 multi-neighbor cases, and 1,596 cases with no
exact neighbor-line hit. The earlier 110/14 figures covered only effectively
literal clean/marker cases because the diagnostic had not been updated when
headword-expression candidates were introduced. With current production
semantics, clean/marker-only misses still contribute those original 110 unique
and 14 multi-neighbor cases; residual parenthesis expressions add 99 unique and
21 multi-neighbor cases, and residual slash expressions add one multi-neighbor
case. The majority (86.7%) still have no exact neighbor hit, so line drift is
not an automatic fallback. Longer local offset runs are tracked separately and
references are never shifted from lexical coincidence alone.

Residual malformed/uncertain source references, out-of-CUC annotations,
non-textual entries, and missing CUC lines are explicitly accounted rather than
guessed.

The separately pinned thesis Appendix is used as a concordance audit, not as a
source of invented fragment nodes. Reviewed CUC 0.2.8 has no fragment/RS identity
mapping, so multi-RS and conflicting/incomplete findspot evidence remains source
evidence rather than a fabricated fragment model.

## Migration from earlier pre-release module designs

The primary `module` command now means the corrected feature-only lane schema.
The old JSON-valued feature module remains available only through
`module-v1`.

Do not reuse an existing output directory for migration. Materialize into a new
directory, validate your queries and local `burns-feature-module-report.json`,
then switch the ordered Text-Fabric locations. Keep the prior output separately
for rollback.

## Agora status

Agora currently registers only the two legacy one-source materializers:

- `burns-workbooks-csv-text-fabric`
- `burns-workbooks-pdf-text-fabric`

Those registrations invoke the deprecated standalone `convert` path. The CUC
feature module needs both the user-local Burns source and the exact CUC parent
resource. Agora parent-resource orchestration is tracked separately and is not
faked by copying CUC into Burns output or enabling an implicit network fallback.
