# Ugarit Context Parsing v0.3.0

This is the first stable GitHub release of the Burns Workbooks materializer.

## What users get

- **Native-v2 CUC extension as the primary product.** `ugarit-context-parsing module`
  verifies the exact reviewed Copenhagen Ugaritic Corpus (CUC) base and writes an
  extended Text-Fabric warp with first-class Burns occurrence nodes
  (`otype=entity`). Existing CUC node IDs and sign slots are preserved.
- **Queryable Burns entities instead of JSON annotation blobs.** Exact lexical
  occurrences carry scalar `burns_headword`, supplied `burns_root`,
  `burns_category`, `burns_semantic_status`, `burns_worksheet_role`, and
  `burns_section` features. Overlapping and multi-word Burns occurrences remain
  distinct entities.
- **Conservative lexical projection.** A native entity is created only for an
  exact contiguous match against reviewed-CUC `g_cons`. Burns headwords are
  source labels, not verified lemmas; no `burns_lemma`, fuzzy morphology, or
  prefix/suffix guess is invented.
- **Tablet-scoped excavation observations.** `burns_locus`, `burns_room`,
  `burns_point`, `burns_depth`, and `burns_disputed` are published only on
  a CUC tablet when all mapped Workbook rows explicitly agree. Conflicting or
  incomplete evidence remains in the local audit sidecar.
- **CSV and PDF inputs.** Generated Workbook CSV directories and the original
  Workbook PDFs feed the same normalization, alignment, audit, and native
  publication model.
- **Exact CUC compatibility contract.** Materialization is bound to
  `DT-UCPH/cuc@ad69400f5446e1c8217af01659c7c10ab00c015b`,
  `tf/0.2.8`, with required-file fingerprints plus structural warp checks
  before publication.
- **Context-Fabric/cfabric-mcp composition.** Load the exact CUC directory first
  and the Burns native directory second. Reviewed-CUC + native Burns queries are
  exercised through the pinned Context-Fabric/cfabric-mcp consumer in CI.
- **One-shot native publication.** Native v2 requires an absent output directory,
  stages a complete artifact, and publishes it with an exclusive no-replace
  operation rather than overwriting an existing v1/v2 directory.
- **Explicit compatibility paths.** `ugarit-context-parsing module-v1` retains
  the previous six JSON-valued CUC feature-module format for migration/rollback.
  The older standalone `convert` command is also retained but deprecated.

## Real-source acceptance and known boundaries

The release gates parse the pinned Burns Workbooks runner-locally:

- 45 worksheets;
- 13,857 source rows;
- 10,419 normalized annotations;
- 4,357 exact lexical occurrences materialized as native entity nodes.

Another 4,993 occurrences resolve structurally to a CUC line but do not establish
an exact contiguous surface match. They remain audit evidence rather than being
promoted through fuzzy matching. Residual malformed/uncertain source references,
out-of-CUC annotations, non-textual entries, and missing CUC lines are likewise
accounted for explicitly rather than guessed.

The separately pinned thesis Appendix is used as a concordance audit, not as a
source of invented fragment nodes. The reviewed CUC snapshot has no fragment/RS
identity mapping; multi-RS and conflicting/incomplete findspot evidence therefore
remains source evidence rather than a fabricated fragment model.

## Migration from the previous module design

The primary `module` command now means native v2. The old JSON-valued feature
module is available only through explicit `module-v1`.

Do not load v1 and v2 Burns outputs together. To migrate, materialize v2 into a
new directory, validate your native queries and local
`burns-entity-report.json`, then switch the ordered Text-Fabric locations.
Keep the old v1 directory for rollback until the migration is accepted.

## Agora status

Agora currently registers only the two legacy one-source materializers:

- `burns-workbooks-csv-text-fabric`
- `burns-workbooks-pdf-text-fabric`

Those registrations invoke the deprecated standalone `convert` path. Native
v2 needs both the user-local Burns source and the exact CUC parent resource.
Agora parent-resource orchestration is tracked separately and is not faked by
copying CUC into Burns output or enabling an implicit network fallback.
