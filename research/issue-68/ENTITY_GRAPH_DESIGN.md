# #68 Entity-node architecture decision: experimental derived corpus

## Verified TF contracts (2026-09-16)

The TF data model defines `otype`/`oslots` as a corpus warp, and a *module* as features built around the same warp. A feature-only Burns overlay cannot add individually addressable annotation nodes: https://annotation.github.io/text-fabric/tf/about/datamodel.html . The official `tf.dataset.modify` API supports `addTypes={...}` containing `nodeFrom`, `nodeTo`, `nodeSlots`, `nodeFeatures`, and `edgeFeatures`, but writes **a new complete dataset** and warns that added node types can shift existing node numbers: https://annotation.github.io/text-fabric/tf/dataset/modify.html . TF search accepts a node type and scalar constraints, such as `burnsEntity burns_headword=bʿl`, without JSON parsing: https://annotation.github.io/text-fabric/tf/about/searchusage.html .

**Decision:** prototype a separate derived CUC+Burns TF corpus with an actual `burnsEntity` node for every *exact lexical occurrence*, attached to the source CUC sign slots via `oslots`. Preserve the source's annotation/occurrence IDs only in local audit output, not on every word. Add scalar `burns_headword`, `burns_root` (if recorded), `burns_category`, `burns_semantic_status`, and `burns_worksheet_role` to *entity nodes*. Multiple annotations sharing one word become distinct entity nodes, and multiword labels reside on the encompassing entity rather than falsely as a word's lemma. The source headword is not a verified linguistic lemma. Excluded homographs and structurally ambiguous matches must not yield positive lexical entities; keep the information in the sidecar. Archaeological data will be tablet-level only when same-tablet observations agree; conflicting fragments/locations stay in the sidecar pending a fragment model.

This is an **experimental alternative** to the current feature-only materializer, NOT its API-compatible replacement and NOT an assertion that CUC node IDs remain identical. First RED/GREEN gate builds a pure exact-occurrence-to-slot entity model; second gate proves actual TF materialization/search on a synthetic CUC base and audits original-to-derived node IDs. If `tf.dataset.modify` renumbers CUC, record an explicit mapping and test consumers before advertising the output as composable; never falsify the original CUC fingerprint or assume unchanged IDs. New full-corpus output has nontrivial disk and memory costs; measure on the real reviewed corpus before choosing production architecture, and do not publish Burns-derived corpora.

The real 45 workbook CSVs, Appendix and reviewed-CUC local files are unavailable in this tool session. Synthetic results cannot answer real overlap frequency, source category-directory fidelity, findspot conflict prevalence, runtime performance, or consumer compatibility. Therefore #68 and draft #69 remain open until those checks and the actual user-facing CLI/writer migration pass.
